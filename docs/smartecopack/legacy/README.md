Матеріали, отримані з краулу `smartecopack.com` від **02.04.2025** (982 URL).

| Файл | Що це |

## Рішення про слаги

**Слаги товарів переносяться зі старого сайту без змін.** Це рішення клієнта, і воно
економить цілу мапу 301: правило `/products/:slug → /product/:slug/` покриває всі
299 позицій один в один.

Тому колонка `слаг` у шаблоні **вже заповнена й змінювати її не можна**. Імпорт
бере слаг саме звідти й не генерує його з назви. Якщо слаг лишити порожнім,
імпорт спрацює, але покаже попередження: старе посилання на цей товар після
запуску віддасть 404.

Колонка приймає і чистий слаг, і повний URL старого сайту — зайве відсікається
автоматично.

## Фото

Колонка `фото` — шлях або ім'я файлу. Найпростіший варіант, який не потребує
ручного зіставлення: **назвати файли слагами товарів**.

```
public/products/stakan-kraft-odnosharovij-350-ml.jpg
public/products/krishka-bila-st-90.jpg
```

Тоді колонку `фото` можна не заповнювати взагалі — вона підставиться зі слага.
Якщо іменування інше (за артикулом, за номером із 1С), пришліть архів як є:
зіставлення робиться скриптом, вручну перейменовувати 299 файлів не треба.

Поки фото немає, у картці показується силует за формою товару — сітка виглядає
цілісно, а не як список порожніх прямокутників.

## Порядок імпорту

```bash
cd web
npm run catalog:import ../docs/smartecopack/legacy/products-import-template.csv
npm run check:legacy      # чи не з'явиться 404 на старих адресах
```

Той самий файл можна завантажити через адмінку: **/admin/import/**.

Правило одне: **якщо у файлі є хоч одна помилка, не пишеться нічого**. Половина
імпортованого каталогу гірша за жодного.

`npm run check:legacy` — ворота запуску. Він перевіряє дві речі:

1. усі 159 правил мапи 301 ведуть на сторінку, яка існує;
2. усі 299 старих посилань на товари ведуть на живу картку.

Поки скрипт не каже «✓ Міграція URL готова до запуску», перемикати домен не можна.
