# SmartEcoPack — сайт

Каталог паперової та крафтової упаковки для HoReCa з кошиком-заявкою
та адмінкою. Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 +
PostgreSQL (Prisma).

Проєктна документація — у `../docs/smartecopack/`, розгортання — у `deploy/`.

## Запуск

Потрібен PostgreSQL. Кластер має бути створений з UTF-8-локаллю — при
локалі `C` база не згортає кирилицю в нижній регістр (див. розділ
«Пошук» нижче).

```bash
cp .env.example .env      # заповнити DATABASE_URL
npm install               # postinstall викликає prisma generate
npx prisma migrate deploy # схема
npm run db:seed           # початкове наповнення
npm run admin:create -- ви@приклад.com "надійний-пароль" "Ваше ім'я"

npm run dev               # http://localhost:3000, адмінка на /admin/
```

### Команди

| Команда | Що робить |
|---|---|
| `npm run dev` / `build` / `start` | розробка, збірка, запуск |
| `npm run typecheck` / `lint` | типи й лінт |
| `npm run test:e2e` | e2e у Chromium проти продакшн-збірки |
| `npm run db:seed` | наповнити БД із файлів-джерел |
| `npm run db:studio` | візуальний перегляд бази |
| `npm run catalog:import -- файл.csv` | імпорт каталогу з CSV |
| `npm run catalog:generate` | перегенерувати демо-каталог у products.json |
| `npm run admin:create -- email пароль ім'я` | користувач адмінки |

Змінні оточення описані в `.env.example`. Без `NEXT_PUBLIC_SITE_URL`
canonical, hreflang і sitemap візьмуть значення за замовчуванням із
`src/lib/site.ts`; без `NEXT_PUBLIC_GA_ID` аналітика не вантажиться зовсім.

### Чому два дерева маршрутів, а не `[locale]`

Стандартний підхід — один сегмент `[locale]` і rewrite у proxy (колишній
middleware) для
української версії в корені. У цій версії Next такий rewrite ламає клієнтську
навігацію: RSC-запити до переписаного шляху повертають 404, і `<Link>` не
змінює сторінку. Тому обидві мови — реальні дерева маршрутів над спільними
реалізаціями в `src/views/`. Дублюються лише тонкі обгортки (8–12 рядків).

**Додаючи сторінку, створіть обгортку в обох деревах** — інакше сторінка
з'явиться тільки однією мовою.

## Каталог товарів

Джерело даних на рантаймі — PostgreSQL. Файли в `src/data/` — це **сід**:
з них наповнюється порожня база, далі правки робляться в адмінці або
імпортом.

Зараз у базі **згенерований демо-каталог** — 107 позицій з реалістичними
розмірами й цінами, але це не бойові дані.

### Імпорт реального вивантаження

```bash
npm run catalog:import -- ../docs/smartecopack/legacy/products.csv
```

Те саме доступно в адмінці: **Імпорт** → завантажити файл. Обидва шляхи
використовують один модуль `src/lib/product-import.ts`, тож правила
валідації не можуть розійтися. Опис колонок — на сторінці імпорту
й у коментарі до модуля.

При будь-якій помилці не записується нічого: половина імпортованого
каталогу гірша за жодного.

## Адмінка

`/admin/` — вхід, далі огляд, заявки, товари, категорії, блог, імпорт.

Ціна, наявність і позначка «хіт» правляться просто у списку товарів —
це те, що змінюється щодня. Після кожного збереження викликається
`revalidatePath`, тому зміна одразу видно на статичній сторінці сайту.

Сесія зберігається в БД, а не в підписаній cookie: вихід і видалення
користувача діють миттєво. Розділ закритий у `robots.txt`, метаданими
й окремим правилом у `deploy/nginx.conf`.

## Пошук

Пошук працює по полю `Product.searchText` — нормалізованому в нижній
регістр рядку з назвами обома мовами, артикулом, розміром і значеннями
фасетів. Його будує застосунок (`src/lib/search-text.ts`), а не запит
`lower()`/`ILIKE`.

Причина конкретна: результат `lower()` у PostgreSQL залежить від
`LC_CTYPE` кластера, і при локалі `C` кирилиця не згортається взагалі —
`lower('СТАКАН')` повертає `СТАКАН`. Пошук за «Стакан» мовчки перестає
знаходити товари, і помітити це на локальній машині з іншою локаллю
неможливо. JS-ий `toLowerCase()` працює за Unicode завжди.

## Заявки

`POST /api/lead/` спершу зберігає заявку в БД і лише потім намагається
сповістити менеджера. Якщо Telegram недоступний або SMTP відмовив,
заявка не втрачається — вона видна в адмінці з поміткою про невдалу
доставку й текстом помилки.

Канали вмикаються наявністю змінних `TELEGRAM_BOT_TOKEN` +
`TELEGRAM_CHAT_ID` та `SMTP_HOST`. Онлайн-оплати немає навмисно:
менеджер підтверджує наявність і виставляє рахунок.

## Зображення

Фотографій товарів ще немає. Замість «сірих квадратів» компонент
`Placeholder` малює силует за формою товару (`shape`). Коли з'являться фото:

1. Покласти файли в `public/products/` або на CDN
2. Проставити `image` у товарах
3. У `ProductCard` і на сторінці товару замінити `<Placeholder>` на
   `next/image` — поле в типі вже передбачене

## Редиректи зі старого сайту

`src/lib/legacy-redirects.ts` — 26 точкових правил і 4 шаблонні.
Правила застосовуються транзитивно й виконуються в `proxy.ts` **до**
нормалізації слеша, тому старий URL веде на новий за один хоп (301).

`skipTrailingSlashRedirect: true` у `next.config.ts` потрібен саме для цього —
без нього Next спершу додає слеш (308) і лише потім спрацьовує редирект.

⚠️ Мапа неповна: бракує повного переліку URL товарів і слагів статей
старого сайту. Потрібен краул перед запуском — див.
`../docs/smartecopack/04-zapusk.md`.
