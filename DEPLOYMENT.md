# Розгортання сервісу — інструкція для IT-фахівця

Цей документ — усе необхідне, щоб розмістити застосунок на сервері так,
щоб менеджери заходили в браузері з будь-якої точки світу.

## Що це за застосунок

Веб-система виставлення рахунків та видаткових накладних для ТОВ без ПДВ.

- **Стек:** Node.js + Express + EJS (серверний рендеринг, без React/Vue,
  без етапу збірки). База даних — вбудований SQLite (`node:sqlite`),
  окремий сервер БД не потрібен.
- **Дані** — один файл `data/invoices.db` (+ WAL-файли поруч) і тека
  `data/uploads/` із прикріпленими файлами договорів. Це єдине, що
  потребує резервного копіювання (докладніше нижче).
- Застосунок **не потребує етапу збірки** — жодного `npm run build`,
  просто `npm install` і `node server.js`.

## 1. Вимоги до сервера

- **Node.js 22.5 або новіше** (використовується вбудований `node:sqlite`,
  доступний лише з цієї версії).
- Будь-яка ОС — Linux, Windows Server або macOS; увесь код і всі
  залежності (Node.js, LibreOffice, Docker) кросплатформні. Для VPS
  зазвичай найпростіше й найдешевше — Ubuntu/Debian.
- Порт назовні (за замовчуванням **3000**, змінюється через `PORT`).
- Мінімум 1 ГБ оперативної пам'яті для самого застосунку; якщо ставите
  й OnlyOffice Document Server (крок 6, необов'язковий) — плюс ще 2 ГБ.
- Диск: застосунок сам важить дуже мало, основне місце займуть завантажені
  файли договорів у `data/uploads/` — плануйте з запасом під це.

## 2. Як отримати код

Репозиторій на GitHub: `SergiiPereyaslov/-`, гілка
`claude/auto-invoice-web-interface-bm5w11`. Власник репозиторію (Сергій)
має додати вас як колаборатора з правом читання, або вивантажити код
у зручний для вас спосіб (ZIP-архів тощо).

```bash
git clone -b claude/auto-invoice-web-interface-bm5w11 https://github.com/SergiiPereyaslov/-.git invoice-web
cd invoice-web
```

## 3. Встановлення й перший запуск

```bash
npm install
npm start
```

Відкрийте `http://<адреса-сервера>:3000`. Обліковий запис за
замовчуванням: **логін `admin`, пароль `admin`** — одразу після першого
входу змініть пароль (розділ «Користувачі») і заповніть «Реквізити»
(дані ТОВ, банківські рахунки).

## 4. Постійна робота як сервіс

Щоб застосунок сам перезапускався після падіння чи перезавантаження
сервера — [pm2](https://pm2.keymetrics.io/):

```bash
npm install -g pm2
pm2 start server.js --name invoice-web
pm2 save
pm2 startup   # виведе команду для автозапуску після перезавантаження сервера — виконайте її
```

Так само підійде звичайний `systemd`-юніт, якщо у вас так прийнято в
інфраструктурі.

## 5. HTTPS (обов'язково)

Логін і пароль передаються звичайним HTTP, тож поза локальною мережею
**обов'язково** потрібен HTTPS. Найпростіше — зворотний проксі:
[Caddy](https://caddyserver.com/) (сам випускає й оновлює сертифікат
Let's Encrypt, налаштування в одному файлі) або nginx + certbot. Проксі
приймає з'єднання на 443, перенаправляє на `localhost:3000`, де працює
застосунок.

Приклад `Caddyfile` (замініть домен на свій):

```
rahunky.example.com {
    reverse_proxy localhost:3000
}
```

Після налаштування HTTPS увімкніть у застосунку два прапорці (обидва
вимкнені за замовчуванням, щоб не заважати локальному тестуванню без
HTTPS):

```bash
TRUST_PROXY=1 COOKIE_SECURE=1 PORT=3000 pm2 start server.js --name invoice-web
```

- `TRUST_PROXY=1` — щоб Express правильно розпізнавав з'єднання через проксі.
- `COOKIE_SECURE=1` — щоб сесія передавалася лише зашифрованим з'єднанням
  (без HTTPS увімкнений разом із цим прапорцем логін просто не спрацює —
  вмикайте лише після того, як HTTPS дійсно працює).

## 6. Перегляд файлів договорів у браузері (LibreOffice, рекомендовано)

У картці замовника менеджер може переглянути й роздрукувати прикріплений
Word/Excel-файл прямо в браузері — конвертація в PDF на льоту через
[LibreOffice](https://www.libreoffice.org/). Без нього ця функція просто
недоступна (кнопка «Друк»/перегляд для офісних файлів покаже повідомлення
й запропонує завантаження — нічого не ламається), тож крок необов'язковий,
але бажаний.

```bash
# Ubuntu/Debian
sudo apt install libreoffice
```

Застосунок сам шукає `soffice` на PATH і в типових шляхах встановлення —
додаткового налаштування не потрібно, достатньо встановити.

## 7. Редагування договорів у браузері (OnlyOffice, необов'язково)

Функція «Редагувати» (повноцінний редактор Word/Excel прямо в браузері
із збереженням назад у файл) працює через окремий сервіс — **OnlyOffice
Document Server**, який запускається через Docker поруч із застосунком.
Якщо не потрібна — просто пропустіть цей крок, кнопка «Редагувати» не
з'явиться, решта сервісу працює як завжди.

**7.1. Встановіть Docker**, якщо його ще немає на сервері:
[docs.docker.com/engine/install](https://docs.docker.com/engine/install/)
(для Ubuntu — офіційний скрипт `curl -fsSL https://get.docker.com | sh`).

**7.2. Запустіть Document Server** з увімкненим JWT-захистом (для
розгортання назовні це не «необов'язково», а обов'язково — інакше будь-хто,
хто знає адресу Document Server, теоретично міг би підмінити документ):

```bash
docker run -d -p 8082:80 --name onlyoffice-ds --restart unless-stopped \
  -e JWT_ENABLED=true \
  -e JWT_SECRET=<придумайте-довгий-випадковий-рядок> \
  onlyoffice/documentserver
```

Перевірте: `http://<адреса-сервера>:8082` має показати вітальну сторінку
OnlyOffice. Якщо порт 8082 не повинен бути відкритий назовні (Document
Server потрібен лише самому застосунку й браузерам менеджерів через той
самий домен/проксі) — налаштуйте проксі так, щоб приховати внутрішній
порт, або обмежте доступ фаєрволом і проксуйте `/web-apps`, `/cache` тощо
через той самий зворотний проксі, що й основний застосунок.

**7.3. Додайте три змінні оточення** до запуску застосунку (той самий
секрет, що й у кроці 7.2):

```bash
ONLYOFFICE_URL=https://<публічна-адреса-document-server> \
ONLYOFFICE_CALLBACK_URL=http://localhost:8082 \
ONLYOFFICE_JWT_SECRET=<той-самий-секрет-що-в-кроці-7.2> \
pm2 start server.js --name invoice-web
```

- `ONLYOFFICE_URL` — адреса, яку відкриває **браузер менеджера**, щоб
  завантажити сам редактор. Має бути доступна ззовні (як і сам застосунок).
- `ONLYOFFICE_CALLBACK_URL` — адреса, за якою **сам Document Server**
  звертається назад до застосунку. Якщо обидва (застосунок і Document
  Server) працюють на одному сервері — досить `http://localhost:<PORT>`;
  якщо Document Server у Docker на тому самому сервері — `http://host.docker.internal:<PORT>`
  (Linux: якщо `host.docker.internal` не резолвиться, додайте контейнеру
  `--add-host=host.docker.internal:host-gateway` при запуску).

Підтримувані для редагування формати: Word (.doc, .docx, .odt, .rtf,
.txt) і Excel (.xls, .xlsx).

## 8. Домен (необов'язково, але зручно)

Наприклад `rahunky.example.com` замість IP-адреси з портом — підключається
через DNS-запис (A-запис на IP сервера) незалежно від самого застосунку,
можна додати будь-коли пізніше без переналаштування коду.

## 9. Резервне копіювання

**Найважливіший пункт.** Копіюйте каталог `data/` цілком — там і база
(`invoices.db` + `.db-shm`/`.db-wal`), і всі завантажені файли договорів
(`data/uploads/`). Відновлення після збою — просто повернути каталог на
місце й перезапустити застосунок.

Налаштуйте автоматичне копіювання, наприклад `cron` раз на добу:

```bash
# приклад: щоденна копія о 3:00 у сховище через rclone
0 3 * * * tar -czf /backup/invoice-web-$(date +\%F).tar.gz -C /шлях/до/invoice-web data && rclone copy /backup remote:invoice-backups
```

## 10. Оновлення застосунку в майбутньому

Коли з'являться нові зміни в коді (від розробника):

```bash
cd /шлях/до/invoice-web
git pull origin claude/auto-invoice-web-interface-bm5w11
npm install
pm2 restart invoice-web
```

`data/` не чіпається при оновленні коду — оновлення безпечне для наявних
даних.

## Підсумок: повний список змінних оточення

| Змінна | Обов'язкова? | Призначення |
|---|---|---|
| `PORT` | ні (типово 3000) | На якому порту слухати |
| `TRUST_PROXY` | так, якщо є HTTPS-проксі | `1` — Express довіряє заголовкам проксі |
| `COOKIE_SECURE` | так, якщо є HTTPS | `1` — кукі сесії лише через HTTPS |
| `ONLYOFFICE_URL` | ні (лише для редагування) | Публічна адреса Document Server для браузера |
| `ONLYOFFICE_CALLBACK_URL` | ні (лише для редагування) | Адреса застосунку, якою користується сам Document Server |
| `ONLYOFFICE_JWT_SECRET` | так, якщо увімкнено OnlyOffice назовні | Спільний секрет застосунку й Document Server |
