# 🧾 Веб-система виставлення рахунків

Веб-інтерфейс для виставлення рахунків та видаткових накладних замість Excel.
Створений для **ТОВ без ПДВ**, розрахований на **кількох менеджерів** зі спільною
базою. Інтерфейс і документи — українською.

## Можливості

- **Рахунок + видаткова накладна** з однаковими даними та номером.
- **Друк комплекту** однією кнопкою: **2 рахунки + 2 видаткові накладні**, по два
  документи формату **А5 на одному аркуші А4** (аркуш можна розрізати навпіл).
- **Стандартний український вигляд** документів; сума прописом українською з
  правильними родовими формами.
- **База замовників** (уже завантажено 238) із **пошуком за повною назвою, короткою
  назвою та кодом**, сортуванням і пагінацією. У формі рахунку замовник обирається
  через автодоповнення. У назвах застосовано узгоджені скорочення (ВСП, ДПТНЗ, КЗВО тощо).
- **Каталог товарів** (уже завантажено перелік продукції) — швидке додавання
  позицій; **ціну менеджер проставляє вручну** для кожного рахунку (різні регіони).
- **Кілька банківських рахунків** — при виставленні рахунку менеджер обирає, на
  який рахунок платити; один можна позначити типовим.
- **Дату можна не вказувати** — для бюджетних установ, які платять не день-у-день;
  у документі тоді залишається місце під дату для заповнення від руки.
- **Папка замовника**: реквізити, договір, **прикріплені файли** (Word, PDF, скани —
  завантажуються й зберігаються поруч із замовником) та історія документів із
  сортуванням **спочатку нові / спочатку старі** й кнопкою **«Копія»**.
- **Історія рахунків** із пошуком, фільтрами та статусами оплати.
- **Автоматична нумерація**, **логін менеджерів**, облік автора, керування
  користувачами, копіювання рахунку.

## Початкові дані

При першому запуску (якщо база порожня) автоматично завантажуються:
- **замовники** з `seed/institutions.json` (розділ «Замовники»);
- **товари** з `seed/products.json` (розділ «Товари та послуги»), усі з ціною 0.

Дані завантажуються лише один раз і не перезаписують ваші зміни.

### Долити нових замовників у наповнену базу

Перелік замовників живий: з часом з'являються нові. Щоб додати їх до бази,
у якій уже є дані, впишіть їх у `seed/institutions.json` і виконайте:

```bash
npm run import:institutions               # додасть лише тих, яких ще немає
npm run import:institutions -- --dry      # лише показати, нічого не змінювати
npm run import:institutions -- --replace  # видалити наявних і залити заново
```

`--replace` не торкається замовників, по яких уже є рахунки: інакше історія
документів втратила б зв'язок із замовником. Видалення й заливання виконуються
однією транзакцією, тож збій не залишить базу напівпорожньою.

Команда порівнює замовників за кодом і за назвою (без огляду на лапки, апострофи
та регістр), тож дублів не створює — її можна запускати повторно.

## Вимоги

- **Node.js 22.5+** (використовується вбудований `node:sqlite`).
- База — файл SQLite, окремий сервер БД не потрібен.

## Встановлення та запуск

```bash
npm install
npm start
```

Відкрийте **http://localhost:3000**. Обліковий запис за замовчуванням:
**логін `admin`, пароль `admin`** (одразу змініть пароль і заповніть «Реквізити»).

Порт змінюється через змінну оточення: `PORT=8080 npm start`.

## Перші кроки

1. Увійдіть як `admin` / `admin` і **змініть пароль**.
2. У «Реквізити» заповніть дані ТОВ і **додайте банківські рахунки**.
3. У «Користувачі» додайте менеджерів.
4. Замовники й товари вже завантажені — за потреби додавайте/редагуйте їх.
5. «Новий рахунок» → оберіть замовника (пошуком), рахунок для оплати, додайте позиції
   й ціни, за потреби зніміть дату → **«Друк комплекту»** (2 рахунки + 2 накладні).

## Розгортання для кількох менеджерів

Запустіть застосунок на спільному комп'ютері/сервері в мережі офісу або на VPS;
менеджери заходять у браузері за його адресою. Дані — у файлі `data/invoices.db`
(режим WAL для одночасної роботи).

## Резервне копіювання

Копіюйте каталог **`data/`** — там і база (`invoices.db*`), і завантажені файли
договорів (`data/uploads/`). Відновлення — повернути каталог на місце.

## Структура проєкту

```
server.js               # запуск, автентифікація, дашборд, маршрути
src/
  db.js                 # база (node:sqlite), схема, міграції, seed
  auth.js               # логін, сесії, права доступу
  format.js             # сума прописом, формат грошей і дат
  invoiceHelpers.js     # нумерація, розбір і підрахунок позицій
  routes/               # invoices, clients, services, settings
views/                  # шаблони EJS; друковані документи та комплект
public/                 # CSS та JS (стилі друку: print.css, print-set.css)
seed/                   # початкові дані: institutions.json, products.json
data/                   # база даних SQLite (створюється автоматично)
test/                   # автотести
```

### Прикріпити договори з каталогу на диску

Якщо договори лежать у папках, названих за замовником (по папці на замовника),
їх можна прикріпити однією командою — запускати на тому комп'ютері, де лежать
файли:

```bash
npm run import:contracts -- "F:\2026\Автоматизація ОДЦПІТ"
npm run import:contracts -- "F:\..." --dry   # показати, нічого не змінювати
```

Назва папки зіставляється з назвою замовника з урахуванням скорочень, лапок і
регістру. Повторний запуск не дублює: файл із такою самою назвою й розміром
пропускається. Для папок, яким не знайшлося замовника, команда виводить список —
створіть їх у розділі «Замовники» і запустіть ще раз.

### Скорочення в назвах замовників

Довгі формулювання скорочуються за узгодженою розкладкою (`src/abbreviate.js`):

| Повна форма | Скорочення |
|---|---|
| Відокремлений структурний підрозділ Фаховий коледж | ВСПФК |
| Державний професійно-технічний навчальний заклад | ДПТНЗ |
| Вищий навчальний приватний заклад | ВНПЗ |
| Відокремлений структурний підрозділ | ВСП |
| Комунальний вищий навчальний заклад | КВНЗ |
| Державний вищий навчальний заклад | ДВНЗ |
| Комунальний заклад вищої освіти | КЗВО |
| Комунальний заклад освіти | КЗО |
| Державний навчальний заклад | ДНЗ |
| Відокремлений підрозділ | ВП |
| Вище професійне училище | ВПУ |
| Комунальний заклад | КЗ |

Довші формулювання скорочуються першими, тож «Комунальний заклад вищої освіти»
дає КЗВО, а не «КЗ вищої освіти».
